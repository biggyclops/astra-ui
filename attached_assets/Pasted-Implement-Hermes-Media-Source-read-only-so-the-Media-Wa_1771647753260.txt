Implement “Hermes Media Source” (read-only) so the Media Wall can load real images/videos from Hermes.

Context:
- Hermes serves media over HTTP at:
  http://100.120.145.15:8080/files/...
- Example folder:
  /files/5.%20AI/My%20Favs/vids/
- Hermes likely returns an HTML directory listing (links), not JSON.

Goal:
- Replace/mock media items with real items fetched from Hermes.
- Must work even if Hermes returns plain HTML directory listings.
- Read-only. No deletes, no writes.

Backend (server):
1) Add environment variable:
   HERMES_BASE_URL="http://100.120.145.15:8080"

2) Add endpoint:
   GET /api/media/hermes?path=<urlencoded path>

   - Validate path:
     - must start with "/files/"
     - must not contain ".."
   - Fetch directory listing from:
     `${HERMES_BASE_URL}${path}`
   - Parse results:
     - If response is JSON, use it.
     - Else parse HTML <a href="..."> links.
   - Ignore:
     - parent directory links (../)
     - query-only links
     - folders (href ending with "/") unless includeDirs=true (default false)
   - Identify media types by extension:
     - images: jpg jpeg png webp gif
     - videos: mp4 webm mov mkv
   - Return normalized response:
     {
       source: "hermes",
       path: "<path>",
       items: [
         {
           id: "<stable id from url>",
           type: "image" | "video",
           url: "<absolute Hermes URL>",
           thumb_url: "<same as url for now>",
           filename: "<name>",
           mtime: "<optional if available>",
           size: "<optional if available>"
         }
       ]
     }

3) CORS/Proxy safety:
   - Do NOT fetch Hermes directly from the browser due to CORS.
   - The app server should fetch and return normalized items.
   - For actually serving the media files to the browser, add a proxy route:
     GET /api/media/proxy?url=<encoded absolute Hermes URL>
     - Allow only URLs that start with HERMES_BASE_URL
     - Stream the content through with correct Content-Type
     - Add caching headers (short TTL) if easy

Frontend (client):
4) Add “Source” selector in Media Wall:
   - Mock (default for now) + Hermes
   - When Hermes selected:
     - show a folder path input (prefill: /files/5.%20AI/My%20Favs/vids/)
     - “Load” button calls:
       /api/media/hermes?path=<path>
     - render returned items in the existing grid

5) Use proxy URLs for actual media playback:
   - For each item returned, set display URL to:
     /api/media/proxy?url=<encoded item.url>
   - Keep original Hermes URL in metadata for later.

6) Keep current features working:
   - Filters (All/Videos/Images/Favorites)
   - Loop option (for videos)
   - Drag-and-drop (payload should carry id/type/proxy url/thumb)

UX rules (Lore):
- Hermes is treated as read-only “Archive.”
- No delete/move/rename features.
- Errors must be calm and actionable:
  - “Hermes unreachable”
  - “Path not allowed”
  - “No media found”

Deliverables:
- Working Media Wall that loads real files from Hermes folder path
- Proxy route allows media to display/play in browser without CORS issues
- Minimal code changes; no new heavy dependencies unless necessary
